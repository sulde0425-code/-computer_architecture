本次新增的三个部件（第 5 章）：

① 自研 Radix-2 迭代除法器（新文件 myCPU/divider.v，146 行）
指导书 §5.1 推荐调用 Xilinx Divider Generator IP，§5.2 也允许自行实现电路级除法器。本设计选择了后者，好处是不依赖任何 IP，仿真与上板都能直接跑，也不会因为 IP 未生成而导致综合失败。
接口刻意做成与 Divider Generator 的 AXI-Stream 完全同名同语义，因此日后若想换成 IP，只需用 IP Catalog 生成一个端口一致的除法器直接替换例化即可，EXE 级无需改动： 
divider #(.SIGNED(1)) u_divider_signed   // div.w / mod.w
divider #(.SIGNED(0)) u_divider_unsigned // div.wu / mod.wu
// s_axis_dividend_tvalid/tready/tdata[31:0]
// s_axis_divisor_tvalid /tready/tdata[31:0]
// m_axis_dout_tvalid, m_axis_dout_tdata[63:32]=商, [31:0]=余数
算法为恢复余数法，每拍迭代 1 位、共 32 拍出结果；有符号除先取绝对值再按"商符号 = 被除数符号 ^ 除数符号、余数符号 = 被除数符号"还原，与 LA32R 规定的"商向零取整、余数与被除数同号"完全一致。
算法已用 Python 逐位复现并双重验证：与 func/inst/n30~n36 里的 1060 条真实测试向量逐条对拍，零失配；再与 C 语义参考模型做 2 万组随机交叉验证，零失配。

② EXE 级除法握手与 ready_go 改造（EXE_stage.v）
严格落实了指导书特别强调的两点： 
wire div_req = es_div_inst && !div_sent && !div_done;
assign s_axis_dividend_tvalid = div_req &  es_div_signed;  // 除法指令进 EXE 即置起
// 一旦某拍同时看到 tvalid/tready（握手成功），立即置 div_sent，下一拍撤销 tvalid
if (div_handshake) div_sent <= 1'b1;

// 核心：除法未完成时本级 ready_go 不成立，流水线在此等待
assign es_ready_go = !es_div_inst || es_div_ready;   // es_div_ready = div_done | div_dout_valid
同时把结果锁存到 div_result_r，避免下层反压时丢失；es_to_ms_bus 里送出的已是最终值，因此 ES_TO_MS / MS_TO_WS 位宽不需要变。

③ 除法相关 RAW 冲突处理（ID_stage.v）
除法要占 EXE 几十拍，期间若后继指令要用它的结果，绝不能前递未算完的值。新增了与 Load-Use 完全同构的阻塞： 
assign div_stall = es_is_div && !es_div_ready && (
    (ds_use_rj  && (rf_raddr1 != 5'd0) && (rf_raddr1 == es_forward_dest)) ||
    (ds_use_rkd && (rf_raddr2 != 5'd0) && (rf_raddr2 == es_forward_dest)));

原判断：br_taken 的组合路径为 ID 译码 → 前递 mux → 比较器 → br_bus → IF(~br_taken) → fs_to_ds_valid/bus → ID 级寄存器。 当时这只是经验判断，未做实测。

真正的长路径有两段，分两轮解决：

  1. 乘法器段（第 5 章引入）：DSP48E1 → PCOUT/PCIN 级联 → CARRY4×12（64 位积加法） → EXE 级前递 → ID 级分支比较/跳转目标加法器 → IF next_pc → inst_ram ENARDEN， 数据通路 22ns、逻辑 24 级。 修法：把乘法器从 alu.v 物理移出到 EXE_stage.v， 结果只送 es_to_ms_bus、不进前递路径。→ WNS 改善到 -1.188ns。
  2. 访存段：data_ram(BRAM 输出) → 字节选取/扩展 → ID 前递 mux → 分支比较/转移加法 → IF next_pc → inst_ram 地址译码 → inst_ram ENARDEN， 20.21ns，其中布线 15.30ns 占 75.6%。 修法：给分支单开一条"不含 BRAM"的前递通路 （MEM_stage.v 新增输出 ms_forward_data_alu = ms_alu_result， ID 级新增 rj_br_value/rkd_br_value，分支比较与 jirl 转移目标全部改用它们）。
★ 一个值得记住的方法论教训：修这条访存路径时曾走过一步弯路—— 先只加了"分支不消费 MEM 级 load 前递值"的功能规则（branch_load_stall）， 结果违例端点从 752 降到 371、TNS 从 -282ns 降到 -124ns，但 WNS 从 -1.188 变成 -1.264ns，几乎没动。 原因：只要那个含 BRAM 的信号还挂在多路选择器的"数据输入"上，静态时序分析就会照常分析这条路径； 综合器的常量传播只认常量，不认运行期 select。 要切断组合路径，必须换"数据源"，不能只让多路选择器"不选它"。

修复后结果：cpu_clk_clk_pll WNS = +0.782ns、TNS = 0、违例端点 0 / 10442， 保持时间 0 违例，TIMING-16 告警 274 → 0； 关键路径起点已从 data_ram 的 RAMB36 变为 ID 级触发器 fs_to_ds_bus_r_reg[58]。完整过程见 5.4 节。
