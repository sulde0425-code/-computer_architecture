1.2 九条算逻指令：编码与译码表达式

全部取自 ID_stage.v 的真实译码。LA32R 的算逻指令分两大族：

① 立即数族（opcode[31:26] = 0x00，靠 [25:22] 区分）

指令[25:22]功能译码表达式
slti0x8rd ← (rj <signed imm) ? 1 : 0op_31_26_d[0x00] & op_25_22_d[0x8]
sltui0x9rd ← (rj <unsigned imm) ? 1 : 0op_31_26_d[0x00] & op_25_22_d[0x9]
andi0xdrd ← rj & immop_25_22_d[0xd]
ori0xerd ← rj | immop_25_22_d[0xe]
xori0xfrd ← rj ^ immop_25_22_d[0xf]

② 寄存器移位族（opcode = 0x00，[25:22]=0x0，[21:20]=0x1，靠 [19:15] 区分）

指令[19:15]功能
sll.w0x0erd ← rj << rk[4:0]
srl.w0x0frd ← rj >> rk[4:0]（逻辑）
sra.w0x10rd ← rj >>> rk[4:0]（算术）

③ pcaddu12i（opcode = 0x07）

// pcaddu12i rd, si20  →  rd = PC + (SignExtend(si20) << 12)
// lu12i.w   rd, si20  →  rd =          si20 << 12
// 两者共用同一条立即数通路，区别只在 ALU 源操作数 1 是 PC 还是 0
assign inst_pcaddu12i = op_31_26_d[6'h07] & ~ds_inst[25];
assign src1_is_pc     = inst_jirl | inst_bl | inst_pcaddu12i;
★ 坑 1：pcaddu12i 和 lu12i.w 的 opcode 只差一位，而且都要看 inst[25]。
lu12i.w 是 op=0x05 & ~inst[25]，pcaddu12i 是 op=0x07 & ~inst[25]。 如果不加 ~inst[25] 这个限定，会误判成别的指令族。 更典型的是第 6 章的 ertn 与 tlbwr：06483800 与 06483000 只差 bit12 （见 §7 的 Q6）。

1.3 立即数扩展：第 3 章最容易写错的地方

LA32R 的立即数不是统一的，不同指令族格式完全不同。工程里用一组 need_* 信号先分类、再扩展：

类型位宽扩展方式用在哪些指令
si1212符号扩展addi.w、ld.*、st.*、slti、sltui
ui1212零扩展andi、ori、xori
ui55零扩展（取自 rk 字段）slli.w、srli.w、srai.w
si2020符号扩展后左移 12 位lu12i.w、pcaddu12i
si1616符号扩展后左移 2 位beq、bne、blt、bge、bltu、bgeu、jirl
si2626符号扩展后左移 2 位b、bl

代码是一条优先级链（注意顺序不能乱）：

assign need_si12 = inst_addi_w | inst_ld_all | inst_st_all | inst_slti | inst_sltui;
assign need_si16 = inst_jirl | inst_beq | inst_bne | inst_blt | inst_bge | inst_bltu | inst_bgeu;
assign need_si20 = inst_lu12i_w | inst_pcaddu12i;
assign need_si26 = inst_b | inst_bl;
assign src2_is_4 = inst_jirl | inst_bl;          // 链接地址 PC+4

// 立即数扩展：按"哪一种立即数"逐类处理，未命中的指令取 0
assign ds_imm = src2_is_4 ? 32'h4                          // jirl/bl：链接值 PC+4
                : need_si20 ? {i20[19:0], 12'b0}             // lu12i.w / pcaddu12i
                : need_ui5  ? {27'b0, rk[4:0]}                  // slli/srli/srai.w
                : need_ui12 ? {20'b0, i12[11:0]}                // andi / ori / xori
                : need_si12 ? {{20{i12[11]}}, i12[11:0]}        // addi/ld/st/slti/sltui
                :             32'b0;                          // 未译码指令：给 0，别用脏值
★ 坑 2（最容易错，没有之一）：sltui 的"u"是指比较无符号，不是立即数零扩展。
按龙芯架构手册，sltui rd, rj, si12 的立即数是 si12——先符号扩展到 32 位， 然后才和 rj 做无符号比较。所以代码里 inst_sltui 挂在 need_si12 而不是 need_ui12。
如果照着"名字里有 u 就零扩展"的直觉写，那么当立即数为负数（如 sltui v0, t0, 0xf80）时， 零扩展得到 0x00000f80，符号扩展得到 0xffffff80 —— 两者对 t0 的比较结果完全不同， 而 func 测试里专门有这种负值样例（见 n22/n23 的测试数据），一测就红。
记忆口诀：andi/ori/xori 零扩展（ui12），其余 si12 全符号扩展。 理由：与/或/异或是位操作，立即数被当成"掩码"，零扩展最自然； 其余指令的立即数被当成"数值"，所以符号扩展。

1.4 ALU：第 3 章零改动，但必须讲清独热码

这是汇报时的加分点。工程里的 ALU 用 16 位独热操作码，而不是常见的 4 位二进制编码：

位运算由哪些指令驱动
0addadd.w、addi.w、ld.*、st.*、jirl、bl、pcaddu12i
1subsub.w
2sltslt、slti
3sltusltu、sltui
4andand、andi
5nornor
6oror、ori
7xorxor、xori
8sllslli.w、sll.w
9srlsrli.w、srl.w
10srasrai.w、sra.w
11luilu12i.w
12–14mul.w / mulh.w / mulh.wu第 5 章，不在 alu.v 内实现

结果选择不用 casez，而是一棵并行 "与-或" 树：

assign alu_result = ({32{op_add | op_sub}} & add_sub_res)
                  | ({32{op_slt}}          & {31'b0, slt_res})
                  | ({32{op_sltu}}         & {31'b0, sltu_res})
                  | ({32{op_and}}          & and_res)
                  | ... ;
老师可能问："为什么用独热码？16 位不是浪费寄存器位宽吗？"
答：① 独热码下每个运算部件各自算各自的，结果用一个与-或树汇合，没有优先编码链， 关键路径 = 一个运算 + 一级与-或，比 4→16 译码后再选择短； ② 位宽代价只在级间总线上（几十比特），换来的时序余量在 50MHz 下很值； ③ 扩展性好——第 5 章加乘法只需占位 12–14，不动已有编码。
⚠ 但也要注意：乘法器不能并进这棵与-或树，否则会被吸进前递逻辑锥（见第 5 章讲义）。

1.5 关键设计：gr_we 必须写成"正向或"

★ 坑 3：写回使能不能用"反向屏蔽"，必须用"正向列举"。
很多同学沿用的写法是 gr_we = ~inst_st_w & ~inst_beq & ...（把不写寄存器的指令排除掉）。 这在指令集固定不变时没问题，但第 4 章新增 ld.b 时若忘了往屏蔽式里加， ld.b 就会带着 gr_we=1、alu_op=0（=add）走进默认通路， 执行 rd = rj + rk 并写回 —— 不会报错，只是寄存器被静默改坏，这种 bug 极难定位。 
// 正向译码：只有确实写通用寄存器的指令才置 gr_we
assign gr_we = inst_add_w  | inst_sub_w | inst_slt  | inst_sltu |
               inst_nor    | inst_and   | inst_or   | inst_xor  |
               inst_slli_w | inst_srli_w| inst_srai_w|
               inst_addi_w | inst_lu12i_w |
               inst_slti   | inst_sltui | inst_andi | inst_ori | inst_xori |
               inst_pcaddu12i | inst_sll_w | inst_srl_w | inst_sra_w |
               inst_jirl   | inst_bl    | inst_ld_all | ... ;

1.6 同类指令的"汇总信号"

第 4 章一加就是 6 条访存指令，如果每条地方都写一遍 inst_ld_w | inst_ld_b | ...， 漏一个就是 bug。工程里统一先汇总：

wire inst_ld_all = inst_ld_w | inst_ld_b | inst_ld_h | inst_ld_bu | inst_ld_hu;
wire inst_st_all = inst_st_w | inst_st_b | inst_st_h;

// 之后所有地方只用汇总信号——新增指令只要改这一行
assign need_si12  = inst_addi_w | inst_ld_all | inst_st_all | inst_slti | inst_sltui;
assign res_from_mem = inst_ld_all;
assign mem_we       = inst_st_all;
这是一个可以主动讲的设计习惯：指令集是会增长的（第 3 章加 13 条、第 4 章加 6 条、第 5 章加 8 条）， 所以任何"某类指令"的判定都应当收敛到一处。老师问"你怎么保证加指令不出错"时，这就是答案的一半， 另一半是 §6 的自动化比对。

2.2 比较逻辑：有符号 / 无符号只差一个 $signed

assign rj_eq_rd  = (rj_br_value  == rkd_br_value);
wire   rj_lt_rd  = ($signed(rj_br_value) < $signed(rkd_br_value));  // 有符号
wire   rj_ltu_rd = (rj_br_value  < rkd_br_value);                  // 无符号

然后只用两个比较结果拼出全部六条条件转移：

assign br_taken = (inst_beq  &&  rj_eq_rd
                || inst_bne  && !rj_eq_rd
                || inst_blt  &&  rj_lt_rd
                || inst_bge  && !rj_lt_rd        // 取反即得 >=
                || inst_bltu &&  rj_ltu_rd
                || inst_bgeu && !rj_ltu_rd       // 取反即得 >=u
                || inst_jirl || inst_bl || inst_b
                ) && ds_valid && ds_ready_go;
为什么不直接写 >=？两个理由：
① 省硬件：>= 会再实例化一个比较器，而 !< 复用同一个比较结果，只多一个反相器；
② 避免溢出边角：补码比较里"取反小于"与"大于等于"在数学上完全等价（全序）， 但硬件实现上少一条路径就少一处可能写错的边界。
整数比较是全序，所以 !(a<b) ≡ a>=b 恒成立；浮点因为有 NaN 才不能这么写——但本设计没有浮点。

2.4 分支的两个隐藏依赖（必须处理，否则功能错）

① 分支的比较操作数也要走前递

分支在 ID 级比较 rj 与 rd，如果上一条指令正要写这两个寄存器， 就必须前递，否则比的是旧值。工程里专门为分支铺了第二条前递通路：

// EXE > MEM > WB > 寄存器堆，优先级与通用通路一致
wire [31:0] rj_br_value =
    (es_forward_valid && ds_use_rj && (es_forward_dest == rf_raddr1)) ? es_forward_data :
    (ms_br_fwd_ok     && ds_use_rj && (ms_forward_dest == rf_raddr1)) ? ms_forward_data_alu :
    (ws_forward_valid && ds_use_rj && (ws_forward_dest == rf_raddr1)) ? ws_forward_data :
                                                                          rf_rdata1;

② 分支 + Load-Use：多等一拍（branch_load_stall）

普通的 Load-Use 阻塞只在"EXE 级是 load"时生效。但还有一种情况： load 已经走到 MEM 级，此时它的数据来自 data_sram（BRAM 输出）， 如果直接前递给分支去比较，会连成一条 data_ram(BRAM) → 字节扩展 → ID 前递 → 分支比较 → IF 取指地址 → inst_ram 的超长组合路径 （实测 20.21ns，@50MHz 只有 20ns，不收敛）。

// ① 功能层面：分支一律不消费"MEM 级 load"的前递值
wire mem_fwd_ok = ms_forward_valid && !(ds_is_branch && ms_forward_is_load);

// ② 物理层面：分支在 MEM 级改取 ms_forward_data_alu（发自触发器，与 BRAM 无关）
wire ms_br_fwd_ok = ms_forward_valid && !ms_forward_is_load;

// ③ 时序上让分支多等一拍，下一拍由 WB 级 ws_forward 提供结果
assign branch_load_stall = ds_is_branch && ms_forward_valid && ms_forward_is_load && (
    (ds_use_rj  && (rf_raddr1 != 5'd0) && (rf_raddr1 == ms_forward_dest)) ||
    (ds_use_rkd && (rf_raddr2 != 5'd0) && (rf_raddr2 == ms_forward_dest)));
这里有一个非常值得在汇报时强调的工程经验：
"功能上不选"和"物理上切断"是两件事，必须成对做。 实测只加 branch_load_stall（功能上不选）时，违例端点从 752 降到 371、TNS 从 −282ns 降到 −124ns， 但 WNS 纹丝不动（−1.26ns）——因为只要 ms_forward_data 仍是多路选择器的数据输入， 静态时序分析就会照常分析这条路径。必须换数据源（改用 ms_forward_data_alu）， 让逻辑锥的起点从 BRAM 变成触发器，路径才真正断开。

3 · 第 4 章 · 访存指令的添加

3.1 指导书的实验要求

4.1　st.b 和 st.h 指令的添加
实现的关键在于控制如何实现字节或者半字的写入。显然是通过字节写使能来实现的。 例如 st.b 是写入一个字节的数据，所以他的写使能需要根据 vaddr 的最后两位进行判断。
　　00 → 0001　　01 → 0010　　10 → 0100　　11 → 1000
st.h 指令同理，最后只需要生成写数据即可。　　00 → 0011　　10 → 1100

4.2　ld.b、ld.h、ld.bu、ld.hu 指令的添加
分析与 ld.w 指令之间的异同：
■ 他们之间的计算虚地址，操作数来源，虚实地址映射的方法规则是完全一样的
■ 访存结果都写回 rd 项寄存器
■ 差异仅仅是写回的数据的位宽是不同的
……唯一需要考虑的是如何从数据 RAM 中选择出所需要的内容，可以通过一个多路选择器去实现， 选择信号是根据指令的访存地址的最低两位以及访存操作的类型信息共同决定的。
不要忘记将取回内容扩展至 32 位，记得判断是符号扩展还是零扩展。

——《计算机组成原理实验指导书》第 4 章

3.2 编码

指令opcode[31:26][25:22]功能扩展
ld.b0x0a0x0rd ← 字节符号
ld.h0x0a0x1rd ← 半字符号
ld.w0x0a0x2rd ← 字—
st.b0x0a0x4存字节—
st.h0x0a0x5存半字—
st.w0x0a0x6存字—
ld.bu0x0a0x8rd ← 字节零
ld.hu0x0a0x9rd ← 半字零

工程里用两个汇总信号把它们收拢（见 §1.6），并把"宽度 / 符号"编码成两比特级的字段：

wire [2:0] ds_mem_size = (inst_ld_b | inst_ld_bu | inst_st_b) ? 3'd1 :
                             (inst_ld_h | inst_ld_hu | inst_st_h) ? 3'd2 : 3'd4;
wire       ds_ld_signed = inst_ld_b | inst_ld_h;
为什么要编码成 mem_size=1/2/4 而不是直接传指令信号？
因为 MEM 级离译码器有两级之远，把 6 条指令的信号一路传过去既占位宽又容易漏； 编码成 3 位"宽度"后，MEM 级只需要关心 size 和 signed 两个字段， 将来再加 ld.wu 之类也不用改 MEM 级。

3.3 Store 通路：字节写使能 + 写数据"复制"

关键在于两点：用地址低两位生成 4 位字节写使能；写数据复制到对应通道。

wire [1:0] es_addr_low = alu_result[1:0];

wire [3:0] we_byte = 4'b0001 << es_addr_low;            // st.b
wire [3:0] we_half = es_addr_low[1] ? 4'b1100 : 4'b0011;  // st.h
wire [3:0] we_word = 4'b1111;                           // st.w

wire [31:0] wdata_byte = {4{es_rkd_value[7:0]}};       // 字节复制 4 份
wire [31:0] wdata_half = {2{es_rkd_value[15:0]}};      // 半字复制 2 份

wire [3:0]   es_store_we    = (es_mem_size == 3'd1) ? we_byte :
                                 (es_mem_size == 3'd2) ? we_half : we_word;
wire [31:0] es_store_wdata = (es_mem_size == 3'd1) ? wdata_byte :
                                 (es_mem_size == 3'd2) ? wdata_half : es_rkd_value;
零逻辑。 半字同理：复制 2 份，we=0011 或 1100。
图 4A · 字节写使能：地址低两位决定通道，写数据靠"复制"免掉移位器
对齐说明：st.h 的合法地址要求 addr[1:0] 为 00 或 10（半字对齐）， 所以译码只区分 addr[1]；st.b 任意字节地址都合法，所以要用完整的 addr[1:0]。 （地址非对齐异常 ALE 属于第 6 章扩展档，本课设的 EXP4/5/6 不检测。）

3.4 Load 通路：字节选取 + 符号/零扩展

为什么必须在 MEM 级做？因为数据 RAM 是同步读：EXE 级发出地址 → MEM 级才拿得到 data_sram_rdata。 所以"从整字里挑出需要的字节/半字，再扩展到 32 位"这一步只能放在 MEM 级。

wire [1:0] ms_addr_low = ms_alu_result[1:0];

// ① 字节选取：00/01/10/11 → byte0/1/2/3（小端）
wire [7:0] ld_byte = (ms_addr_low == 2'b00) ? data_sram_rdata[ 7: 0] :
                          (ms_addr_low == 2'b01) ? data_sram_rdata[15: 8] :
                          (ms_addr_low == 2'b10) ? data_sram_rdata[23:16] :
                                                     data_sram_rdata[31:24];
// ② 半字选取：addr[1]=0 取低半字，=1 取高半字
wire [15:0] ld_half = ms_addr_low[1] ? data_sram_rdata[31:16]
                                           : data_sram_rdata[15: 0];

// ③ 按 size 选通路 + 按 signed 选扩展方式
wire [31:0] mem_load_data = (ms_mem_size == 3'd1) ?
                                    (ms_ld_signed ? {{24{ld_byte[7]}},  ld_byte}  // 符号
                                                  : {24'b0,            ld_byte}) // 零
                                : (ms_mem_size == 3'd2) ?
                                    (ms_ld_signed ? {{16{ld_half[15]}}, ld_half}
                                                  : {16'b0,            ld_half})
                                :   data_sram_rdata;   // 字访问直接取整字

wire [31:0] ms_final_result = ms_res_from_mem ? mem_load_data : ms_alu_result;
图 4B · Load 的两级处理：先按地址选字节/半字，再按指令决定符号或零扩展

3.5 访存接口的三个易错点

问题正确做法
片选何时拉高？ data_sram_en = es_valid && !flush && (es_res_from_mem || es_mem_we)。 只有真正访存的指令才使能，其余指令必须保持为 0，否则会读到脏数据或误触发写。
地址给几位？ CPU 侧给完整的 32 位 alu_result；低两位留给字节选择逻辑用， 由 SoC（bridge_1x2）截取 [19:2] 再送给 RAM。 不要在 CPU 里提前丢掉低两位，否则 st.b / ld.b 就没法选通道了。
写使能与写数据的关系？ 4 位 we 是字节粒度的；写数据用"复制"铺满 32 位， 两者配合即可定位到目标字节，不需要动态移位。

4 · EXP4 / EXP5 / EXP6 各自测了什么（测试点全表）

4.1 先说清：一个"测试点"是什么

func 测试程序位于 mycpu_env/func/，每个指令一个测试函数（inst/nXX_*.S）， 由 init.S 里的 inst_test 依次调用。测试长这样（以 slti 为例）：

/* 22 */
#define TEST_SLTI(in_a, in_b, ref) \
    LI (t0, in_a); \          // ① 把被测操作数装进寄存器
    LI (v1, ref);  \          // ② 把"参考结果"装进另一个寄存器
    slti v0, t0, in_b; \      // ③ 执行被测指令
    bne v0, v1, inst_error    // ④ 不等 → 跳 inst_error（测试失败）

// 每个测试函数开头：
LEAF(n22_slti_test)
    addi.w s0, s0, 1          // 测试点编号 +1（s0 全程累加，用作"进度条"）
    ...
    TEST_SLTI(0xd9d129b5, 0x988, 0x1)   // 几十组随机数据 + 参考值
    ...
为什么这么设计？因为没有操作系统、没有 printf。 测试程序只能靠"执行到第几个测试点"来表达进度：跑完一个测试函数就把 s0 加一， testbench 监测到 s0 变化就打印一行 Number 8'd22 Functional Test Point PASS!!!。 所以"测试点 PASS 数"＝"被验证通过的指令数"——这也是平台判分的依据。

4.3 测试是怎么"自动"比对出来的

测试宏里的 ref（参考值）不是手写出来的，而是由交叉编译器在编译期算好的： TEST_SLTI(in_a, in_b, ref) 中 ref 由宿主工具链按 LoongArch 语义计算后作为立即数编进程序。 CPU 跑出来的 v0 与它不等就跳 inst_error。 这等于用"另一套独立实现的 LoongArch 语义"给你的 CPU 当阅卷老师，比自己写波形断言可靠得多。

仿真侧还有第二重保险：把 CPU 每条指令的写回结果（debug_wb_pc / debug_wb_rf_wen / wnum / wdata） 逐拍与官方黄金模型产生的 golden_trace.txt 比对， 任何一条对不上就立即报错并停在当前 PC，可以直接定位到出错的那条指令。

★ 坑 5（本项目历史上最贵的一个坑）：只换 coe 不出新 bit。
Xilinx IP 采用 OOC（Out-Of-Context）综合，真正把程序烧进 BRAM 的是 loongson.runs/inst_ram_synth_1/inst_ram.dcp。 如果只用 generate_target 而不显式 reset_run + launch_runs inst_ram_synth_1， dcp 不会重新生成，于是"镜像换了、bit 没换"—— 历史上所有 bit 里固化的一直是第一套程序，评测平台按各章测试点判分，结果每章都是同一个分数。

  5. 升华：体会"数据通路复用"与"控制信号收敛"两个设计原则。

7.2 老师常问的 8 个问题

Q1：为什么 sll.w 和 slli.w 可以共用同一个 ALU 运算？
因为 ALU 只看 alu_src2 的低 5 位（shift_amt = alu_src2[4:0]）， 至于这个 5 位来自指令的 ui5 字段还是来自 rk 寄存器，是 ID 级 src2_is_imm 决定的事。 通路相同、来源不同——这就是复用的本质。
Q2：pcaddu12i 和 lu12i.w 的区别？
立即数通路完全一样（都是 {i20, 12'b0}），区别只在 ALU 源 1： lu12i.w 用 0（结果 = imm<<12），pcaddu12i 用 PC（结果 = PC + imm<<12）。 所以硬件上只多了一个 src1_is_pc 多路选择器。
Q3：blt 和 bltu 硬件上差在哪？
差在比较器：$signed(a) < $signed(b) 与 a < b。 前者看补码符号位，后者纯按数值二进制比。 典型对照：a = 0xffffffff, b = 0x00000001 时， blt 成立（−1 < 1），bltu 不成立（4294967295 > 1）。
Q4：为什么 ld 的字节选取必须放在 MEM 级？
因为本设计的 data RAM 是同步读：EXE 级给出地址， 数据在 MEM 级那拍才出现在 data_sram_rdata 上。 没有数据就无从选取，所以选取与扩展只能跟在 MEM 级。 （若强行挪到 EXE 级，就得"提前一拍猜数据"，做不到。）
Q5：st.b 为什么不直接把数据左移到位？
能这么做，但代价是一个 32 位动态移位器（两级 LUT + 进位链）。 改用"复制 4 份 + 4 位字节写使能"后，移位逻辑彻底消失， BRAM 的每个字节通道都收到相同数据，由 we 决定谁真正写入。 这是"用存储器的字节使能换逻辑资源"的典型技巧。
Q6：加新指令时，最怕漏改什么地方？
三处：① 译码表达式（尤其是 opcode 只差一两位的指令对，如 ertn=06483800 与 tlbwr=06483000 只差 bit12，必须整体比对而不是位域匹配）； ② 前递相关的 ds_use_rj / ds_use_rkd（漏了就用旧值）； ③ gr_we（漏了就不写回，或更糟——用反向屏蔽写法时误写回垃圾值）。
Q7：仿真和上板为什么会不一致？
因为它们不吃同一个文件。仿真用行为级 sync_ram.v 读 func/obj/inst_ram.mif； 出 bit 用 Xilinx IP 读 func/obj/inst_ram.coe，还要经 OOC 综合生成 inst_ram.dcp。 任何一边漏同步（尤其是只 generate_target 而没重跑 OOC）就会出现"仿真对、上板错"。 正确做法：换章统一走 switch_exp.sh。
Q8：怎么证明 bit 里装的就是这一章的程序？
可以反向验证：从 inst_ram_synth_1/inst_ram.dcp 导出 256 个 RAMB36E1 的 INIT_01 初值，与由 coe 推导出的期望值做多重集比对。 布局模型是 64 block × 4 byte-lane，每个 RAMB36 存 4096 字中的一个字节通道， INIT_k 覆盖 block 内字 [32k … 32k+31]， 字节序为 b[31−j] = word(base+j) 的第 lane 字节。
⚠ 注意：ex4/ex5/ex6 三套程序前 8223 字完全相同， 必须取 word[8224] 之后的数据才判别得出来。
